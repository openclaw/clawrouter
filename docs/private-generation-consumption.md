# Private generation consumption — local source candidate

This inactive slice starts at PR976's qualified retained-generation foundation.
It does not activate ordinary proxy, HTTP, Access, direct, provider or credential
cache callers. The ordinary entrypoints remain unchanged. Publication is held
for source qualification of the DATA/CONTROL inventory below. The own-request
fixed-cohort contract, six custody repairs and private retained credential
destination are implemented in this candidate. The new prefetch warms only that
owned destination; ordinary foreground acceleration needs a future owned adapter.
Authored semantics remain
`UNRUN_CODE_ONLY_HOSTED`; static arithmetic is not a runtime result.

## Closed ownership

`completeConsumableCredentialGeneration` records explicit provider/token-reference,
all-connections, snapshot, selection and session facets before hydration. The
record has positive independent common-arena backing and a frozen private copy.
Only the real generation slot binds that coverage to the admitted graph. The old
`completeCredentialGeneration` API gains no inferred coverage.

Coverage follows the slot through optional promotion and actual retirement.
Promotion accounts its metadata in the existing shared vector. Refusal retains
the original admitted temporary owner. Neither a stable key nor missing result
fields establish coverage.

`authenticateCredentialGeneration` verifies the genuine borrower and actual
binding, compares explicit facets, then applies the credential/digest/expiry,
policy-generation and owner rules. Its capability exposes only status/code and
disposal. The identity, effective policy and full admission remain private. A
preverification proof, forged handle, old coverage-free borrower or mismatched
facet cannot authenticate. Business denials retain their private owner until
explicit disposal; unavailable resolution still throws.

A separate parent borrow funds every authentication lifetime. A selection holds
its authentication owner independently of the public authentication capability.
A hint holds the detached selection independently of its public selection
capability. Disposing a public handle clears that handle's WeakMap association;
only the last actual child clears the graph aliases and releases credit. A
publication eviction has no authority to release these children.

## Local planning and advisory state

The base admission stays frozen. A separate owned overlay stores mutable counts,
cursors. Authority-bound runtime observations have their own detached, positively
funded owners, indexed by grant key and ordinary grant revision. A successor starts
with empty local counts/cursor and its own authoritative snapshot. There is no full-admission clone.

The new selector uses the ordinary accepted candidate range and existing strategy
helpers, including random draws, ordering, priorities, pin/exclusion, retry and
configured-pool behavior. It does not call the private bridge's 98-choice-limited
selector. Configuration probes acquire the existing bounded preparation owner;
capacity escapes ordinary configuration-error suppression.

A snapshot-select hydration returns a genuine single-use originating selection
receipt. The first authentication consumes that receipt; revalidation preserves
the authority choice without a second count/cursor effect. Later cache borrowers
choose locally. If matching pending runtime exists during hydration, the private
request defers selection using snapshot-only, as the ordinary admission cache
does. Requested coverage remains explicit; no receipt is invented.

Selection first plans a complete result, validates the logical whole admission
with overlay substitutions, funds and copies the complete selected record, and
funds pending/advisory metadata. Only then can counts or cursors change. Unknown
selected-record fields survive the detached copy. The new copy has its own owner;
it is not described as another reference to the retained base graph.

Runtime merging calls the unchanged `mergeGrantRuntimeState`. Its detached
output and pending feedback copy have separate backing. Account, extra-usage and
snapshot aliases cannot borrow already-retired input credit. Pending records
hold genuine parent borrowers through original ACK settlement. Flushes delete
only the exact pending object that they sent. A replacement arriving during a
write remains pending; attempted records are not replayed. Counter cursor writes
use the latest accepted record for that pool.

Explicit flush uses the existing bounded authority ACK reader. Its original
read, FIRSTcancel, unlock and late-body joins remain authoritative. UNKNOWN leaves
that promise pending and retains the parent and all backing. No timer or response
publication is retirement evidence.

96 MiB counter. A promoted ticket's zero balance is never reused as scratch.
The DO arena remains independent. A lease replacement admits the complete next
amount before changing its debit; failure preserves the old debit. These are
normative application charges, not object sizes or physical-heap guarantees.

Every independent lease is a positive exact charge against the same 96 MiB
counter. These prospective expressions describe application components, not all
concurrent native invocations, caller-owned inputs or engine internals. Source
qualification must verify the ceilings against the actual call paths.

### DATA overlaps and admission order

For a closed JSON tree, `D = 8*(C + 2*M + E + V) + 2*U`, conservatively counting
all values as primitive occurrences. Each reservation uses actual counts. New
strings count at every retained occurrence; no interning discount. Execution
indexes/records stay CONTROL even when they also require payload bytes.

- Hydration keeps its full original owner and separately funds explicit coverage.
  Coverage survives promotion/eviction with its own metadata receipt.
- Authentication funds effective policy separately from the original generation.
  Refresh funds the successor before replacement; old children retain the old
  owner and its debit.
- Selection funds working vectors and the largest sequential inspection/config
  vector, then admits/funds the full selected copy, overlay, pending record and
  cohort before counters, cursors, hints or scheduling effects.
- Runtime separately owns work, local copy and pending copy. Added timestamp
  members are counted before merge, including overwritten candidates. Old local
  aliases clear before release; replaced inflight feedback stays with its original.
- Flush funds `34816 + 2*T`, with `T <= 2097152` the largest prospectively planned
  escaped envelope, at most 4229120 bytes. One row is in transport at a time.
  The fixed portion includes two 4 KiB header sets, 128-byte ACK backings/text,
  parser and terminal metadata. Request records retain their separate funding.

## Closed owned prefetch receipt

The seventh-file boundary adds `prefetchOwnedGrantCredentials` beside the
unchanged ordinary void API. `prepareCredentialGenerationPrefetch` validates a
real hint and actual authority binding, reserves positive common-arena backing,
and acquires a separate hint child before any registration. It copies only the
required credential binding and scalar cache configuration. It exposes no grant,
materializer callback, loader or result graph.

The cache module alone mints a nonescaping permit. The preflight module's named
materialization command requires that permit and the genuine single-use cap.
Only the private destination receives the independently parsed
reply. The public receipt contains `accepted` and, on acceptance, only
`completed: Promise<void>`.

OFF, HIT and rejected background registration start no materialization. They
unwind only the provisional child. Accepted work immediately observes both
outcomes of the original private materialization operation, including synchronous
throws from the start boundary. It never calls ordinary `credentials.peek/load`.
The child survives publication/hint eviction, an own
request's scalar publication wait, and becoming the loader after that wait.
The private original includes publication-finally and the existing materialization
fetch/read/FIRSTcancel/unlock joins. UNKNOWN holds the original promise, receipt,
child and backing. Cleanup clears command, binding, original-work and hint
aliases before releasing the child and settling the void receipt. Independent
registration and cleanup failures remain separate origins, including shared
reason objects and literal undefined.

Publication identity is a frozen empty scalar token, not a foreign run object,
promise or graph carrier. Polling uses only the invoking request's timer roots.
A late original whose token was invalidated cannot publish. Expiry, eviction and
replacement unpublish; they never release an outstanding value borrower.

The lazy index is partitioned by actual authority binding and actual credential
owner binding, then the ordinary key/generation/revision ID. Root, authority,
partition and entry reservations all precede their factories. Each 2048-byte,
64-field fixed component includes its exact-charge/vector receipt, index/owner
fields, fixed property-name occurrences, flags and scalar cells. The entry adds
`4*I` for its two retained ID occurrences, including the Map key. A value's
1024-byte, 64-field component covers its owner, receipt/charge, timestamps,
publication/borrower fields and fixed property names. These are conservative
normative components, not JS object weights. Empty indexes clear binding/ID/map
aliases before releasing their actual reservations.

The graph vector is measured without encoding, stringifying, cloning or key
arrays; deep freezing is separately prepaid under the full temporary component.
Every retained string occurrence is counted. The existing record profile bounds
graph payload by `2*1048576 + 8*65536 = 2621440` and structure by
`16384 + 49152 = 65536`; actual measurements, not those maxima, enter the shared
ledger. Closed parsed JSON has no owned byte backings. Escaped serialized
eligibility is measured exactly. The existing single optional 8 MiB payload,
8 MiB aggregate serialized and 524288 structural coordinates remain unchanged.

`PrivateCacheReservation.reserve` admits the complete new value/metadata vector
and obtains a new positive exact debit from the SAME Worker 96 MiB counter while
the full 32 MiB source component remains charged. The synchronous commit checks
publication identity again, installs the funded entry and detaches the old
publication. Old borrowers keep the old debit. Only then do materialized-value,
original-promise, command and hint aliases clear and the temporary owner retire.
There is no temporary-to-retained conversion, forged split or free 8 MiB backing.
Optional refusal preserves an existing entry, clears the unused result after
original cleanup and returns a void completion. It does not deny authentication.
Genuine materialization/cleanup failures still reject, including literal undefined.

`borrowOwnedGrantCredentials` consumes a genuine hint cap and returns only a
frozen dispose-only capability. It neither starts an RPC nor returns a grant.
Its new 4096-byte caller-lived metadata and lazy 512-byte registry have positive
common backing before factories/ref increments, even when optional coordinates
are full. `adoptCredentialGenerationDestination` checks the actual selected-owner,
authority, credential binding and exact ID before atomically invalidating the old
cap and attaching a new dispose-only child. ID/provenance traversal has a separate
full temporary reservation; adopted children keep the old graph's debit. Last
actual selected-child disposal clears that alias before release. Forged, cloned,
consumed and double-disposed capabilities fail. No provider consumer is wired.

This receipt owns the hint alias and the new private destination transition. It
does not fund the unrelated ordinary credential cache or retire a remote DO, and
does not claim native producer retirement, a physical ACK or a heap bound.

The current implementation reserves a 32 MiB temporary component for the new
materialization chain, plus separately backed lazy registries. ID conversion,
configuration normalization and retained ID occurrences are checked before their
factories. The numerical rows above include the original materialization, private load,
source and terminal overlap. They are submitted for source qualification; actual
hosted semantics remain UNRUN. No unused PR976 slots are treated as credit.

## Originating-request fixed cohorts

ROOT adopted the own-originating-request cohort contract. A consuming operation
prospectively funds and fixes at most four count/runtime claims, including its new
record first, before publishing counters/runtime state. This is a flush batching
boundary, not a record/profile acceptance cap. Excess unclaimed observations keep
their existing parents and charges for a later originating-request flush.

The complete outbound envelope is planned before claims/effects; its escaped
text is independently funded, not borrowed from pending-record credit. Each
cohort owns its claim lists, fixed cursor flags, parent, original work,
followers and failure cleanup. Unstarted registration rejection restores only
that cohort's provisional claims and returns a genuine funded `pending` cap.
The cap survives public auth/selection/borrower disposal and eviction. Its
single-use `drain()` prospectively claims a fixed cohort in the invoking request
and consumes its existing owner; it never awaits or starts work in a foreign
request. Explicit `dispose()` is allowed only after all unattempted rows have
transferred to other started owners. It cannot discard unattempted obligations. Accepted work starts in the accepting request;
no shared slot contains a scheduled completion or queued successor. No foreign
completion is awaited, and no successor is launched from another request's
continuation. A new count after an in-flight claim starts with its own delta,
without adding the already-claimed delta again.

The selection handle exposes only its own operation's scalar/void `flush`
receipt in addition to its existing closed methods. Runtime feedback returns the
same receipt type. Receipts belong to their originating caller/request, are not
stored in the shared generation slot, and expose no graph. Hints retain only the
private selected owner, not a public operation receipt.

`flushCredentialGenerationRuntime` synchronously claims its own fixed cohort
and returns that original completion. It is not a global drain of foreign work
or future updates. Each attempted row joins its original transport/read/ACK
cleanup, deletes only an identical pending record, clears its claim aliases,
and retires its independent parent. Known independent cleanup failures are
retained while the remaining fixed rows are attempted. A lost ACK is not
replayed. UNKNOWN keeps the original and the entire remaining cohort funded.

There is no visibility polling API, timeout retirement credit, self-join or
public-response delay. Ordinary advisory cursor ordering is unchanged; this
slice makes no stronger global ordering promise.

The new Node witnesses distinguish A's held original from B's completion and
exercise a four-record cutoff with 41 accepted deltas. The native fixture creates
separate A/B HTTP invocations over the same genuine published generation. A's
actual authority reply remains held while B claims and completes its own row;
the SQL total must be two, both before and after A's release. The fixture gate
shares only scalars and polls on each native request's own timer roots. It neither
awaits a foreign gate promise nor adds a production visibility API. The original
requests, response bodies and release-first fixture control are joined.

## Six-repair custody and funding delta

Shared runtime observations copy the ordinary merged value before publication.
The old observation stays funded until its last synchronous view has copied it;
replacement clears the old alias before release. Matching views use actual
binding identity plus the ordinary grant revision, merge with each live slot's
own authoritative state and enter complete-overlay profile admission. ACK clears
only the exact pending value. It does not clear the shared observation needed by
an older live owner. Empty authority partitions clear every observation before
retiring its debit. No predecessor counts, foreign promises or caller graphs are
stored in this view.

The private runtime index has a separate 512-byte owner before its first factory;
its fields clear before that owner releases. Ordinary foundation metadata,
including its exact 230-byte borrower debit, is unchanged. The new originating
receipt is bound by identity inside the separately funded coverage owner.
Each detached observation has an independent positive owner. Its nested-map key
and revision occurrences, observation/lease/charge and ownership cells use the
explicit `4K + 4R + 1024` component in addition to the full merge-sized component.
Those are CONTROL owners with logical payload backing, not passive data credit.
A cohort claims pending records, not the authority's entire detached observation
history. The active replacement has its own 14-product row; the lookup/copy phase
has 120 additional products. Other retained observations keep their independent
owners and debits. This is not a whole-isolate 1024-object guarantee.

Overlay preparation records the exact prior debit before prospective expansion.
All result, pending, parent and cohort products must succeed before counters or
cursors change. Failure clears transient result/runtime-view aliases, restores
claims, then restores the exact old overlay debit. Repeated late refusal cannot
accumulate the provisional component. The original-selection receipt field is
funded before hydration/borrow factories and moves once into authentication.

The native saturation invocation now stays alive and joins all 64 original
blockers and its observers; other requests expose only readiness/release scalars.
A and B dispose their public capabilities before draining genuine refused-work
caps in their own native contexts. Host dispatch immediately enrolls a memoized
body root for every actual Response, including a late A after assertion failure.
Release-first teardown joins the dynamically growing fetch/body roster before
fixture disposal. Separate body/control failures preserve their occurrences even
when their reasons are the same object or literal undefined.

The new authored cases cover originating A then later B/count parity, repeated
late-debit refusal, live/fresh/revised/foreign-authority runtime observations,
refused work after all public owners disappear, native originating receipts and
pending runtime, native own-request blockers, and host late-body failure origins.
No dependency-backed local semantics ran. The private destination now has its own
prospective retained funding and custody; it never credits legacy credential-cache
publication as a receipt. The complete new candidate still requires immutable
source closure before draft publication and hosted execution before landing.
