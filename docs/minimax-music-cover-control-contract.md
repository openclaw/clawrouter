This slice privately qualifies authority and control ownership after the sealed
input/hash foundation. It has no production caller, discovery entry, provider
POST, upload, response codec or public schema. An opaque preparation record is
not a reusable permit. A later integration must move the same final authority
tail to actual dispatch; it cannot carry this observation across later waits.

The new explicit `minimax-global-music-cover-inline-audio` administrator intent
attests the original scalar API key and account to the closed GLOBAL
`api.minimax.io`, `music-cover`, `inline-audio.v1` profile. Generic eligibility and discovery reject the strict V2 cover profile before
endpoint handling. V1 speech and regular Music retain their exact profiles,
including environment discrimination. CN,
OAuth, URL, feature-ID, free-model and text-Music permission are not inherited.
Imports project authoritative null. Changing a binding rotates lineage.

Owner mutation reuses the complete Music mutation proof and current SQL enabled
administrator check after preparation, hashing and pool admission. Cover changes
also bind the old cover binding in the mutation digest. The final exact proof
comparison precedes storage invocation with no preparation await. Pending or
noncanonical records cannot repair themselves into authority. This is fresh at
the check, not atomic revocation across Durable Objects.

## Admission and authority

A genuine sealed input supplies provisional control ownership synchronously,
after actual digest settlement and before key hashing or canonical admission.
The control root is registered before work starts. An earlier metadata claim,
copied handle, deadline or abort prevents transfer. Only the proxy verifier's
WeakMap identity enables subsequent controls; copied identities cannot bind it.

Canonical admission branches before caches, prefetch, KV imports, projection
repair or alternate selection. Whole SQL row counts and stored byte aggregates
are checked before retrieval and parsing, including rereads. Missing, pending or
oversized canonical state denies the operation. The private selection does not
depend on a generated cover declaration. Owner inspection and materialization
branch before diagnosis, refresh, reconciliation and projection publication.

Each refresh reads the current connection, effective principal policy and model
tariff, then the original owner last. Unknown price under an enforced monetary
budget denies before materialization; explicit `policy_fixed` is separate from
vendor pricing. The second refresh follows all reservations or soft observations
and dispatch-admission acknowledgments. Changed budget/price coverage denies;
there are no additional reservations or automatic reselection.

The existing 96 MiB input charge remains held. This is caller-owned operational
accounting, not measured V8 heap or a platform-native allocation bound.

Each 1 MiB ticket reserves these simultaneous occurrences without GC credit:

| Occurrences | KiB |
| --- | ---: |
| One request graph, bounded scalar/header views and descriptor | 160 |
| One request text, flatten/encoding and observable transport representation | 144 |

The five 1 MiB partitions are ordinary scratch, mandatory scratch,
identity/policy, accounting, and handoff. They are not reused by concurrent lanes.
The handoff partition retains the entire foundation's 640 KiB remainder; only
384 KiB is available for new bridge records. Its closed roots are the control
root/observer, sealed metadata view, original signal/deadline, verifier identity,
selected original grant, immutable budget plan/attempt records, exclusive
finalizer, and opaque inactive result. They reference bounded records or physical
handles, never a cloned Request, environment graph, raw error cause or image copy.
The settled hash snapshot is not credited against concurrently live hash work:
control transfer is unavailable while its actual promise remains pending.

Every control is capped at 16 KiB wire, depth 16, 128 values/members/entries,
8,192 decoded string units, 4,096 units per scalar, 32 headers totaling 4 KiB,
16 KiB whole backing and 8,192 reads including empty reads and EOF. Preflight
precedes copies, serialization and parsing. Original BYOB readers are registered
before header checks. Unqualified default-reader data is rejected before reading.

## Calls, retirement and finalization

| Actual registered path | Ordinary calls |
| --- | ---: |
| Canonical admission | 1 |
| First connection/policy/original-owner refresh | 3 |
| Exact original credential materialization | 1 |
| Four hard reservations OR four completed soft status observations | 4 |
| Four hard dispatch-admission acknowledgments | 4 hard / 0 soft |
| Final connection/policy/original-owner refresh | 3 |
| Actual total | 16 hard / 12 soft |

The future POST ticket remains unused: eventual totals would be 17/13, but this
module cannot dispatch. Fewer configured budget legs use fewer calls. Cold or
oversized canonical state denies; it never initializes outside the counter.

One ordinary and one mandatory physical slot are acquired before serialization
or I/O. The registered flow is serial; independent two-lane scheduler tests are
primitive evidence, not invented actual-path concurrency. A timeout changes the
public result but does not release a slot or the charge. Original pending read,
first cancellation (including rejection), late response and unlock must retire.
Stalled cleanup retains capacity. A bodyless response retires immediately;
an unowned locked body fails closed and cannot certify retirement.

All reservation IDs and the usage event ID exist before ledger I/O. One exclusive
finalizer owns partial admission, without generic internal rollback. It waits
for ordinary physical retirement, then serializes at most four settlements,
their four corresponding queue fallbacks, and usage queue/direct-ingest fallback
(ten mandatory attempts). Each attempt has an independent 15-second execution
window; physical cleanup can remain held beyond it. A fallback waits for its
predecessor's actual retirement. No retry changes the original IDs, and no R2
operation is present. DO-internal ledger/queue processing is not a caller ACK.

The current slice is provably unsent because it has no provider fetch path.
It records `not_dispatched` with null tokens and zero debit; this is not a free
cover generation or a vendor receipt. Future dispatch requires different
terminal evidence before accounting can settle potentially paid work.

Input completion joins the independently registered control root. Control never
awaits input completion or discard. It initiates input closure before joining its
own physical roots. Cleanup rejection is reported separately from successful
retirement; no encompassing completion promise joins itself.
After all physical roots settle and original locks retire, tickets drop their
response, reader, cancellation and work-promise references. The owner removes
its verifier/admission association and caller/phase handles before resolving
the control root. A retained completed flow keeps only bounded counters and
sanitized terminal facts. Pending cleanup keeps the references and charge.
Focused tests inspect those references directly, including rejected first
cancellation; this is not a GC or heap measurement.

## Qualification boundary

The focused tests and isolated Workerd fixture exercise canonical SQL, four
budget legs, immutable IDs, bodyless and lost acknowledgments, serialized
fallback, actual administrator HTTP demotion while a pool acknowledgment is
held, maximum decoded input, full-charge contention, and original read/first
cancel/late-response cleanup. Authored cases are not execution proof. Exact-head
hosted semantic and all required consumer gates must pass before landing.

Maximum-input and control phases are bounded operational evidence, not measured
simultaneous heap liveness. Native HTTP pump/socket allocations and the original
DO storage producer are not silently certified by caller reader retirement.
No producer-ACK contract is introduced. PCM/WAV subtype, duration, vendor limit
units, SSE framing, URL response mapping and live entitlement remain unresolved.
Unary HEX is only a future documented candidate; no response model echo is
invented. Full cover routing, upload, codec compatibility and end-to-end behavior
remain required later work.
