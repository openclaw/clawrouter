# Private owned HTTP Chat staging

This is an inactive implementation checkpoint. The default Worker export and
ordinary HTTP authentication, selection and credential-cache entrypoints remain
unchanged. The named compiled HTTP entry and pinned UNIFIED client witness are
implemented and registered, but the complete vertical is not qualified.
There is no deployment or public header/Env activation.

The request capability owns a positive charge in the existing common Worker
body arena. Authentication remains inside the genuine generation owner; its
result is a scalar verdict or an error Response. An early credential/policy
check does not establish provider, selection or session coverage. Those facets
must match the actual retained generation before their later use.

## Original upload custody

The private preparation branch registers an upload owner before constructing a
source or `FixedLengthStream`. It calls the source's original `pipeTo` directly,
observes its original promise immediately, and retains the fixed stream's
readable side for dispatch. The ordinary preparation branch keeps its existing
`pipeThrough` behavior.

Unused preparation initiates owned abort before joining the pipe. A source
created before a later factory fails receives its own original cancellation.
A source locked without an owned original pipe has unknown custody: its scope
and funding stay held. Successful fetch headers, a public response, a wrapper
EOF, and a timer are not substitutes for original pipe settlement.

The final request consumer joins the original roots before clearing source,
fixed-stream, listener and promise aliases. Independent upload failures retain
their origins, including `undefined` and two occurrences of the same Error.
The public response must not wait on its own encompassing completion.

## Outstanding closure

The request and upload metadata allowances are provisional implementation
components, not a completed DATA/CONTROL proof. The full HTTP overlap with
generation hydration, selection, foreground credentials, accounting, retention
and delivery still requires an actual prospective inventory under the existing
ceilings. This checkpoint grants no new arena, control slots, physical-heap
bound, or default-route coverage.

The full-admission bridge intentionally omits snapshots when a candidate is a
legacy KV grant. The private provider command classifies that selection-coverage
miss only after genuine authentication, requested-facet, policy, connection and
unavailability checks. It owns ordered default-key and KV reads, reuses the pure
candidate planner, and reserves result storage before one `/grant-pools/select`.
Nonrecording selection makes no counting RPC; a lost selection reply is uncertain
and is not replayed. It never writes a second `/grant-pools/record` for that choice.
The immutable generation and its missing snapshot are unchanged.

The Worker candidate phase keeps its own cumulative seven-counter allowance
across optional pool resolution and every original KV record. It does not reset
or reuse the generation's inherited admission ledger. The selection reply keeps
its existing separate bound. Runtime observations are looked up by actual
authority, key and `grantRevision`, and detached under positive funding before
another await can replace their independent owner. This adapter and its SQLite
witnesses remain source-only implementation work, not runtime qualification.

Authored upload witnesses cover a 1 MiB ASCII Chat serialization, unused and
partially constructed uploads, held/rejected original cancellation, independent
failure origins, capacity before source factories, and native SSE-prefix delivery
while cancellation remains held. They are not evidence that the full UNIFIED
entry executes. Local dependency-backed semantics remain unrun; local checks
are syntax and source checks only.

The current local selection checkpoint also covers nonrecording projected choices without consuming the initial-selection receipt. Legacy feedback is admitted through the actual selected owner and its `grantRevision`, rather than inferred snapshot membership. Its pending fixed cohort drains in the originating HTTP finalizer after the other original roots settle. A cohort that cannot start remains owned and funded. Authored Node and native KV/SQLite witnesses cover count-once, nonrecording, mixed candidate order, and revision-isolated pending observations; execution is still pending hosted qualification.

## Compiled HTTP checkpoint

`privateOwnedHttpChat` is a named build entry. It accepts only POST to
`/v1/chat/completions`; the default export and public configuration do not select
it. Catalog discovery in the fixture uses the ordinary control-plane handler.
The pinned OpenClaw plugin selects its actual unified Chat transport from that
catalog. One client matrix row is added; all prior rows remain.

Foreground credentials have a separate, genuine capability. The request reserves
its 32 MiB temporary component after successful secret preverification and before
full admission can count a choice. A covered generation reserves before local
selection. A private destination hit borrows the same immutable credential graph;
misses use original materialization. Optional destination refusal leaves the
temporary owner usable. Prepared callbacks retain that owner through actual
delivery, accounting and archive roots. The finalizer clears proxy aliases before
credential, selected-record and authentication owners. A failed last-consumer
handoff holds funding instead of releasing a dependent owner.

The two shallow selection carriers prospectively charge every copied string key,
primitive and string value occurrence, with the existing 16384-unit model bound.
Nested plain graphs remain borrowed from the intake owner. This component is not
a proof for the later serializer, accounting or complete HTTP phase overlap.
Those DATA and CONTROL tables are still open; the checkpoint is not a candidate
for publication. Node and native tests have only received static syntax checks.

## Intake and delivery checkpoint

The private intake counts whole distinct byte backings before retaining chunk
views. Its existing positive `BodyLease` credit is counted once; an exact common
arena charge supplements that credit before decode or parsed-graph factories.
Small inputs keep native `JSON.parse`, including deep unknown data, duplicate
last-wins fields and own `__proto__` data. A constant-state lexical pass counts
all source container, member, array-element, primitive and decoded string-unit
occurrences before parsing. It creates no key vector, graph or decoded string.
For valid JSON, array elements equal commas plus nonempty containers minus
members. The prospective graph component is `8*(C+2M+E+N)+2U`; duplicate source
members are conservatively included. This is logical application accounting,
not a native-parser allocation or physical-heap estimate.

The full decoded text and prospective graph overlap stays funded through parse.
Only after text/buffer/index aliases clear may the exact supplement shrink.
Expanded input still uses the existing structural limits and parser; its graph,
current scalar concatenation, decoder chunk and original backing are funded
before each feed. No source counter becomes payload credit. The intake does not
change ordinary JSON grammar or impose a new source-size limit.

The private response consumer observes original read, first cancellation and
unlock origins separately. Independent `undefined` or shared-Error rejections
remain separate occurrences. A native errored stream's cancellation can instead
propagate its already-observed read failure without calling the underlying cancel
algorithm; that propagation is classified by original state, never reason
equality. Reader-closed and retirement joins clear original aliases before the
request can release its funding. Unknown locks keep the owner funded.

HTTP selection and runtime feedback reserve their pending work but defer its
transport to the originating finalizer. After delivery/upload/account/archive
roots settle, proxy aliases and selected/credential/authentication consumers
clear before the finalizer starts its own fixed pending cohorts. Pending
capabilities independently retain their parent generation. This avoids starting
feedback while full HTTP consumer graphs are still retained; it is not a claim
that the complete simultaneous CONTROL inventory is closed.

One source ambiguity remains open: the authority's final dependency check can
remove selection and snapshots, producing the same missing-snapshot shape as
legacy completeness fallback. The existing reply has no scalar reason. The
owned caller must distinguish those paths before claiming legacy coverage;
authority source remains unchanged pending a scoped protocol disposition.
