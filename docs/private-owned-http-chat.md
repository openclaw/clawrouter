# Private owned HTTP Chat staging

This is an inactive implementation checkpoint. The default Worker export and
ordinary HTTP authentication, selection and credential-cache entrypoints remain
unchanged. The named compiled HTTP entry and pinned UNIFIED client witness are
implemented and registered, but the complete vertical is not qualified.
There is no deployment or public header/Env activation.

The request capability owns a positive charge in the existing common Worker
body arena. Authentication remains inside the genuine generation owner; its
result is a scalar verdict or an error Response. An early credential/policy
check does not establish provider, selection or session coverage. Those facets
must match the actual retained generation before their later use.

## Original upload custody

The private preparation branch registers an upload owner before constructing a
source or `FixedLengthStream`. It calls the source's original `pipeTo` directly,
observes its original promise immediately, and retains the fixed stream's
readable side for dispatch. The ordinary preparation branch keeps its existing
`pipeThrough` behavior.

Unused preparation initiates owned abort before joining the pipe. A source
created before a later factory fails receives its own original cancellation.
A source locked without an owned original pipe has unknown custody: its scope
and funding stay held. Successful fetch headers, a public response, a wrapper
EOF, and a timer are not substitutes for original pipe settlement.

The final request consumer joins the original roots before clearing source,
fixed-stream, listener and promise aliases. Independent upload failures retain
their origins, including `undefined` and two occurrences of the same Error.
The public response must not wait on its own encompassing completion.

Upload scopes are separate from the logical delivery/accounting completion.
Unused preparation cancels immediately. A dispatched upload can continue while
logical HTTP consumers remain active. When those consumers finish, retirement
initiates cancellation of any still-unsettled upload before joining its original
pipe and scope. Otherwise a provider response that finishes without consuming
the upload could make the upload wait on its own encompassing completion. A
held original cancellation still holds the owner and funding; a public SSE
prefix does not settle it. New Node and native witnesses exercise this dispatched
case, including an independent `undefined` cancellation failure. They are unrun.
