# Private MiniMax cover composition

`composePrivateMiniMaxMusicCover` joins current canonical authority, the original
budget IDs, one upload and the existing partial unary-HEX response owner. No
public factory, route, discovery offer or native client calls it. The older
`prepareInactiveMiniMaxMusicCover` still finishes known-unsent preparation; its
result cannot authorize this POST. The inactive transport fixture remains separate.

## Additive format custody

`beginMiniMaxMusicCoverWaveInput` uses the existing incremental intake, original
reader retirement and hash. After complete intake and before the actual digest,
it borrows one `DataView` to validate a local partial profile: little-endian
RIFF/WAVE, PCM format 1, 16-bit, 48 kHz, one or two channels, 6–360 seconds.
Exactly one 16-byte `fmt ` precedes one `data` chunk. Lengths, zero padding,
byte rate, block alignment, integral sample frames and complete file consumption
must match. At most 32 chunks and 64 KiB of ancillary chunk bytes are accepted.
Compressed, extensible and RF64 inputs are rejected. There is no chunk array,
audio copy or escaping byte view.

A complete decimal 50,000,000-byte stereo file can qualify at 12,499,989 frames;
the equivalent mono file exceeds 360 seconds. These are application limits and
a local format subset, **not vendor compatibility or full-format parity**.
The private owner record binds scalar format facts to the actual settled hash
of the same sealed bytes. Opaque-only input, copied metadata and caller flags
cannot enter composition. The original opaque input API is unchanged.

## Authority and attempt inventory

Canonical admission still rejects cold/oversized/pending state before repair or
fallback. The first refresh resolves the current connection, effective principal
policy and price before materialization. Unknown enforced USD denies before
secrets. Explicit `policy_fixed` is independent of vendor cost.

The serializer remains unpulled while its bounded headers, capsule and cleanup
roots are prepared. All budget and preparation waits precede the final existing
connection → effective policy/coverage → original owner sequence. The handoff
requires the exact successful owner-read ticket to have physically retired and
released its slot, with no ordinary predecessor queued. It synchronously checks
format/input/owner/coverage/deadline, claims the ticket, records invocation and
constructs the sole fetch. There is no post-refresh await, serialization or slot
wait. Changed coverage denies instead of creating extra reservations.

Caller tickets do not count DO-internal work. FIRST cancellation is not another
RPC. One ordinary and one mandatory physical slot remain separate. Every attempt
is nonrefundable and uses its original ID; lost/malformed acknowledgments do not
permit replay. Synchronous invocation throw and asynchronous rejection both
remain potentially paid. Proven pre-invocation denial settles known-unsent;
after invocation, explicit fixed debit remains fixed even on transport failure.
Unknown USD remains `unpriced_request` with null known-cost reporting and tokens;
the numeric zero accumulator is not a price quote. No durable client idempotency
or refund promise is added. There is no R2 leg.

## Independent retirement

The single finalizer is registered before work but first awaits a private
terminal-dispatch decision. Every success/denial/failure seals ordinary admission
before that decision resolves. It then joins actual ordinary retirement; mandatory
admission remains open through settlement and fallback. Fallback waits for its
predecessor's FIRST cancellation, pending read and unlock, including rejection.

Public delivery resolves independently. POST retirement joins upload, fetch/late
response, original response reader and downstream EOF/cancel. Control retirement
joins POST plus finalizer; input closure joins control. Neither delivery nor
finalizer waits for encompassing input/control completion. Unknown lock release
retains the root, slot and charge. After all physical retirement, ticket references,
capsules and verifier associations clear before input release.

## Unchanged operational reservation

Hash remains two 50,000,000-byte occurrences plus the existing 640 KiB remainder.
One borrowed format view, counters and frozen scalar record occupy the existing
32 KiB format and 64 KiB metadata allowances. No new hash-phase graph is added.
Controls/upload remain `50,000,000 + 32 MiB + 16 MiB = 100,331,648` bytes,
leaving 331,648 bytes under the 96 MiB reservation.

The bridge has one final-read token/index, one prepared capsule, one decision
latch/observer, one public result, one POST physical root and one finalizer
registration/observer. The capsule's closed fields are owner, input capability,
execute/discard callbacks, result/physical/source-retired promises, ticket and
used flag. There is no record history, new input copy or raw error archive.
The upload inventory remains 440 KiB; its unused 15,944 KiB cannot be repurposed.
All original control wire/graph/header/backing/read limits remain unchanged.

Only after intake/hash/application-upload retirement and clearing all audio
references does the genuine owner atomically split 32/64 MiB. No release/reacquire
gap or second response acquisition occurs. Failed transfer retains the original
charge. The existing response profile stays partial: 4 MiB decoded audio,
8 MiB + 64 KiB wire, bounded incremental unary HEX and complete EOF, with no
invented response-model echo. After downstream retirement, the residual 32 MiB
can remain held for settlement. No GC credit or simultaneous whole-heap claim is
made; platform-native HTTP storage remains unqualified.

## Proof boundaries

The isolated Workerd fixture uses actual SQL authority/budget/usage objects and
the same stream passed to the synthetic provider POST. It covers four full-50M
hard/soft × native/manifest envelopes, maximum padded controls and the existing
4 MiB output limit, exact upload bytes, original-ID fixed receipts, partial/lost/
malformed acknowledgments, ten-attempt fallback, fresh-price and owner races,
held upload/read/FIRST-cancel rejection, late response, unclaimed delivery and
held settlement. Its unknown-unlock case intentionally retains ownership; runtime
disposal is not application retirement. Handoff forgery/busy-slot injections are
explicit private fault tests, not manufactured RPC concurrency. Maximum evidence
is phased operational evidence, not measured heap allocation.

Runtime results must be bound to the tested head. Source assertions alone do not
qualify these cases. Synthetic authorized Worker composition and the ordinary
consumer matrix do not establish an audio-capable OpenClaw cover client, vendor
PCM compatibility, public routing, SSE, URL output, entitlement or deployment.
