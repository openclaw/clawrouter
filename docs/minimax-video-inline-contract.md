# MiniMax global inline first frame

The private runtime accepts one inline PNG, JPEG or static WebP first frame for
MiniMax-Hailuo-2.3 and MiniMax-Hailuo-02. Public declarations and native-client
activation remain separate. Fast, the three legacy I2V models, CN input, URLs,
uploaded handles, source fetching and remote cancellation remain closed.

An enabled current Access administrator must explicitly attest
`minimax-global-video-inline-first-frame`. This produces the closed
`clawrouter.minimax-video.v2` binding with `inputProfile: inline-first-frame.v1`,
the global origin and the same two models. V1 and CN remain T2V-only. Omission
never upgrades a binding. Existing owner mutation hashing, pool admission,
current SQL authorization, generation/lineage changes and authoritative null
projections apply to the complete binding. The freshness check is not an atomic
transaction across owners.

The frontend selects the declared route before intake. The original proxy-key
authorization precedes the first read. Incremental intake accepts at most
12 MiB JSON wire and 8 MiB decoded image. It retains no complete JSON text,
base64 string, encoded archive or second decoded image. Every acquired read
requires BYOB, a whole backing at most 16 KiB and at most 8192 calls including
EOF. Default-reader input is denied before reading.

Raw wire bytes and decoded token units have separate counters. Each canonical
base64 payload character earns one raw-byte credit. URI prefixes, JSON syntax,
whitespace and escape overhead count against 64 KiB nonimage wire. Feeds are at
most 256 raw bytes; bounded token/decoded scratch is checked before committing
image bytes. Decoded keys determine the exact slot and duplicate identity,
including escaped spellings. Scalar input retains the existing depth16,
128-occurrence, 32768-unit and 16384-unit-per-scalar bounds. Padding, trailing
bits, full EOF, MIME, container and dimensions must all qualify.

The sole image writer is revoked before hashing. A private state binds the
original operation, caller, policy, exact router/upstream model, endpoint,
first-frame slot, MIME, dimensions, populated byte length and content digest.
Bounded scalar input is frozen. The actual WebCrypto promise is registered
before racing cancellation and receives the populated original view directly;
there is no added `.slice()` snapshot. Changed content or effective scalars
under an existing idempotency key conflict. T2V digest bytes are unchanged.

Current policy and pricing checks precede materialization. The inline GLOBAL
V2 check runs inside original-owner revalidation before secret materialization,
then repeats on the fresh original generation/lineage/account/binding before
the sole POST. No caller boolean, reconstructed body or private catalog reply
can mint the input capability. Unknown hard-USD admission remains closed;
`policy_fixed` is an explicit policy tariff, not vendor pricing.

## Constant operational reservation

Each invocation reserves 96 MiB in the existing pool before authentication or
intake. Inline CREATE selects its profile before image allocation. No allowance
is released or reused based on garbage collection, a successful hash or EOF.

| Ownership | MiB | Bound |
| --- | ---: | --- |
| Control tickets and descriptors | 32 | 21 nonrefundable calls: 16 ordinary + 5 mandatory, 1.5 MiB each; 0.5 MiB descriptors |
| Partitioned scratch | 8 | Four ordinary slots plus one mandatory slot; bounded parser/hash/header scratch |
| Private decoded image | 8 | One writer, one original backing, populated view only |
| Hash snapshot allowance | 8 | One actual WebCrypto promise; no caller-side copy |
| Scalars, digest, preparation and lifecycle projection | 8 | Forwarded scalar JSON <=16 KiB; native wire <=1 MiB, depth32/4096 occurrences/262144 string units; projection <=64 KiB |
| Upload/output/delivery | 8 | Whole application chunks <=16 KiB, one pending pull, zero prefetch; no history |
| Charged headroom | 24 | Retained reservation, not a native transport-copy bound |

Control representations retain the T2V finite bounds: 64 KiB wire, depth16,
512 occurrences, 32768 decoded units, scalar16384, 32 headers/4 KiB total,
16 KiB backing and 8192 reads. Queued calls hold bounded descriptors and allocate
serialization only after admission to a physical slot. No nested response/file
charge is acquired. T2V, poll, collector and file profiles remain unchanged.

This is caller-owned operational accounting, not measured heap or a bound on
all platform storage. Native HTTP frames, draining copies, internal pumps and
socket backings are an explicit unqualified follow-up. The 24 MiB is not two
proven 12 MiB native copies. Caller-created streams, chunks, strings, promises,
views and retained records remain inside the application ledger.

## Retirement and publication

The upload serializer is created only after confirmed dispatch admission and
final authorization. Existing-job returns create no serializer. The serializer
reads the exact private image/scalars and emits bounded base64 chunks. It never
receives a second caller body. Its exact length is checked before dispatch.

Register the upload root before constructing fetch. The physical provider slot
joins upload retirement and every returned response, including late responses
and fetch failure. Headers alone release neither slot nor capacity. Start
discard before awaiting retirement. Pending read, first cancellation (including
rejection), source closure, lock, hash, serializer and downstream EOF/cancel are
independently joined without waiting on an encompassing finish from its own
child. A dispatched job remains independent of caller delivery, but keeps its
original absolute deadline. Native internal-pump acknowledgment is not claimed.

The create-response projector counts discarded metadata and preserves rejecting
facts before discarding values: top-level error, premature video URL, wrong
retained-field type, duplicate key and malformed int64. Complete syntax and EOF
precede original-job binding or publication. No upstream URL is fetched.

## Qualification

Focused and actual isolated workerd cases are authored for the full 8 MiB
PNG/JPEG/WebP × two models × native/manifest matrix, actual upload byte equality,
original fixed receipt, content conflict, same-owner reachable maximum controls,
96 MiB contention, held hash/upload/read/first-cancel cleanup, rejection, late or
unclaimed output, V1/CN/import denial and fresh authority across waits.
Authored cases are not execution proof. Final-head hosted results must qualify
the implementation before landing; local dependency refusal permits code-only
inspection and syntax checks, not substitute semantic execution.
