# Frozen xAI realtime voice contract

OpenClaw `31ad71a8addc1d42fbc5478f7e114860f5cbf6c7`:
`extensions/xai/realtime-voice-{config,protocol,bridge}.ts`,
`capability-provider-metadata-factory.ts`, terminal/playback tests and
`src/talk/provider-types.ts`. The finite model is `grok-voice-latest`; voices are
eve, ara, rex, sal and leo. The frozen relay uses mono PCM16 little-endian 24 kHz
or G.711 mu-law 8 kHz, with JSON base64 audio. Newer codecs, binary transport,
SIP, browser token provisioning, custom voices and force-message are outside this
slice. No model alias is silently substituted.

Primary sources checked 2026-11-03:

- [Speech-to-speech guide](https://docs.x.ai/developers/model-capabilities/audio/speech-to-speech):
  model query, audio configuration, function tools, server VAD and optional history
  caching. Cached history expires after 30 minutes without activity; that is not
  a guaranteed durable application session.
- [Voice API reference](https://docs.x.ai/developers/rest-api-reference/inference/voice):
  real HTTP 101 at `wss://api.x.ai/v1/realtime`, server-side Bearer auth, JSON
  session, response, audio, item and cancellation events.
- [Voice pricing](https://docs.x.ai/developers/models/speech-to-speech): default
  server-VAD sessions bill elapsed session duration at $0.08/minute, plus $0.004
  per client text item. Server-requested function outputs are excluded from the
  text fee. Audio byte duration cannot substitute for the session-time meter.
  Qualification of rounding, admitted duration, dispatched messages and actual
  account tariff remains with shared accounting/schema owners.

## Published exports

`worker/xai-realtime-voice.ts` exports `xaiRealtimeVoiceModel`,
`xaiRealtimeVoices`, `prepareXaiRealtimeVoiceQuery`,
`prepareXaiRealtimeVoiceSetup`, and `XaiRealtimeVoiceConnection`.
Sanitized fixtures: `providers/_fixtures/xai/realtime-voice.json`.

The query accepts only the selected frozen model. Raw `conversation_id`, SIP
`call_id`, secrets and unrelated parameters are rejected. Setup checks the
native `session.update` shape: explicit voice/audio, server VAD, `grok-transcribe`
input recognition, optional high/none reasoning, optional history-cache opt-in
and bounded declared function tools. Input/output formats match the frozen
client's common format. Setup is immutable after server acknowledgement.

The class is a connection-local codec, not a socket, durable session store or
replacement orchestration framework. `opened()` follows a runtime-qualified
upgrade. `client()` returns validated native messages. `server()` returns bounded
observations. `acknowledgePlayback()` is called by the trusted host audio sink.
`close()` reports the last known response outcome, unresolved calls, validated
input/text counters and observed audio. These counters do not prove dispatch,
playback, acceptance, actual wall time or billing. New-response uncertainty stays
incomplete. Every observation leaves upstream cost unknown.

## State and ownership boundaries

Input waits for `session.updated`. Client traffic is limited to audio append,
user text, bound function outputs, response create/cancel and owned truncation.
Tool arguments remain provisional through argument-done/output-item-done. Only
a completed response publishes declared function calls. Each output binds once
to a pending call in this connection; unknown or replayed call IDs fail. Failed,
incomplete and cancelled responses do not dispatch their tools. Native JSON is
data and is never executed by this codec.

Native response IDs fence late audio and duplicate terminals. A VAD successor
without the old terminal reports `previousUnsettledId`, not a synthetic vendor
cancellation/refund. Unknown or unidentified terminals fail closed. The shared
runtime must freeze each settlement once and preserve the prior uncertain charge.

Output audio is provisional. Playback completion gates manual follow-up response
creation. Acknowledgements accumulate across chunks. Manual cancellation comes
before truncating even completed playback, matching the frozen bridge; native
VAD owns its interruption and permits truncation without another cancel. Truncate
IDs must belong to observed audio, and duration cannot exceed generated bytes.
The host must additionally use its actual played duration. A no-active-response
cancel acknowledgement neither proves a free turn nor settles another response.

Input transcription completed/updated events are revisable snapshots, not final
utterance boundaries. Source2's actual client owns quiet-period reconciliation.
No duplicate append or fabricated final transcript occurs on connection loss.
Assistant transcript-done is an item observation, not a paid-response terminal.

Local bounds: 1 MiB JSON frame, 128 KiB setup, 64 KiB input audio chunk, 512 KiB
output audio chunk, 32 MiB audio in each direction, 32,768 frames, 1,024 responses
and audio items, 128 pending calls, 1,024 completed calls and 64 KiB tool arguments
or result. These limits are not time/price bounds. The bridge must enforce strict
UTF-8 before passing text frames, deadlines, queue/backpressure and fresh policy.

## Remaining concrete integration

- Source1: existing WebSocket upgrade/selected grant, caller-policy-credential
  ownership, session deadline and admission, uncertain writes, per-response
  settlement and terminal delivery. No automatic replay of input or tool results.
- Source3: existing xAI YAML/schema. Proposed handshake: `xai.realtime_voice`
  for the named model and bidirectional voice capability, plus session-time and
  text-message charging. Do not use standalone STT/TTS tariffs for this protocol.
- Source2: actual gateway-relay voice/Talk consumer, playback acknowledgements,
  transcript correction, barge-in and all-tool-results-before-response ordering.
- Source6: native Worker/socket/client acceptance proof and serialized snapshots.

History-cache opt-in is encoded, but reconnect activation is closed until Source1
resolves a scoped original conversation reference, caller, credential lineage,
policy and pending tool/playback state. Replayed completed tools need durable
deduplication; a raw upstream conversation ID is insufficient. This codec neither
creates a parallel resume store nor claims resumption parity.

Ten deterministic tests qualify the frozen fresh-connection protocol. No live
call, deployment, browser credential issuance, production route activation or
full E12 parity is claimed. Unknown upstream-dollar budgets remain closed; a
policy-fixed charge remains a separate accounting basis.
